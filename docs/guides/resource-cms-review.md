# Resource pages: review before publishing

Changes that Resource staff make to subject pages (for example [ralevel.com/resources/accounting](https://ralevel.com/resources/accounting)) now go through a review before they go live. It works like a pull request on GitHub. Staff submit their changes, and the Resource Dep. Head or an admin looks at exactly what changed. They can approve it, ask for changes, or reject it. Everything is recorded.

**Where to find it:** go to **Admin → Resource CMS**. The **Change requests** link in the sidebar lists every request.

---

## For Resource staff

### 1. Edit and save
Open a subject, make your changes, and click **Save draft**. Nothing is live yet.

### 2. Submit for review
Click **Submit for review**. You'll see every change you're sending, and you can:
- adjust the **title**, which is filled in for you, and
- add **notes for the reviewer**, for example why a link changed.

The subject becomes **read-only while it's in review**. Nobody else on the team can edit it until the review is done, but anyone can read the request and comment on it.

### 3. If changes are requested
You'll see an orange **Changes requested** banner in the editor with the reviewer's note. Edit, click **Save draft**, then click **Resubmit**. The reviewer sees what you changed **since their last review**.

### 4. Approved or rejected
- **Approved:** your changes are live on the site.
- **Rejected:** the request is closed and the subject goes back to what's live. Your work isn't lost. Open the request and click **Restore to draft** to bring it back.

You can **Withdraw** your own request while it's open. That closes it and leaves the draft as it is, so you can keep editing.

---

## For the Resource Dep. Head and admins

### Reviewing
A number next to **Change requests** in the sidebar shows how many requests are waiting. Open one to see:
- **Changes:** every item that was added, removed or updated, with the old and new values side by side.
- **Since last review:** after a resubmission, only what changed since you asked for changes.
- **Activity:** the full history, including comments.

Then choose one:
- **Approve & publish:** the changes go live straight away. A note is optional.
- **Request changes:** it goes back to the author. A note is required, so tell them what to fix.
- **Reject:** the request is closed and the subject's draft goes back to the live page. A note is required.

**Small fixes:** while a request is in review you can still edit the subject yourself, for example to fix a typo. Your saves are added to the request, and the activity shows "edited the request".

You can't approve a request you submitted yourself; owners and admins can.

### Publishing your own edits
Heads and admins don't need a review: the editor shows **Publish** instead of **Submit for review**. Direct publishes are still recorded. While a staff request is open on a subject, approve or reject it first.

### The resources homepage
Only heads and admins can edit the main [/resources](https://ralevel.com/resources) page (featured cards and popular subjects): **Resource CMS → Edit resources page**.

---

## Who can do what

| | Staff | Head / admin |
|---|---|---|
| Edit and save a draft | ✓ (not while it's in review) | ✓ |
| Submit for review | ✓ | – (publishes directly) |
| Comment on a request | ✓ | ✓ |
| Approve, request changes, reject | – | ✓ (not your own) |
| Publish without review | – | ✓ |
| Edit the resources homepage | – | ✓ |

Owners can change who counts as a reviewer: the **Resource publishing** row on **Admin → Page access**.

## What's recorded

Every request keeps the following, permanently:
- who submitted it and everyone who edited the draft beforehand
- every round of review, with the notes and comments
- what was approved and published

Direct publishes are recorded too. **CMS History** still shows every draft save and publish for 90 days, and approvals there are labelled "Approved #N".
